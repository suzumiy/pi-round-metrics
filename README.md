# pi-round-metrics

独立的 Pi 扩展：Working 栏显示动态图标、简洁的“思考中／工作中”状态与七项统计，不显示具体工具名称、随机短句或渐变特效。

Working 栏采用紧凑、整组固定预留宽度布局，图标后一个空格即显示本组数值，所有占位留白补在组末尾；不再把数值右对齐到离图标很远的位置。前两组依次为“平均值 / 本次值”：

```text
⣾ 思考中  ⏳ 1.2/0.8      ⚡ 38.6/~42.5   ⏱️ 1m23s     🔥 ~221k    💰 ≥$0.087
```

模型请求等待和输出阶段显示“思考中”，任何工具执行阶段显示“工作中”（包括读取、写入、命令和MCP工具）。状态按工具调用ID集合判定，支持并行及嵌套工具：全部工具结束后才切回“思考中”，失败的工具同样释放状态。“思考中”只是模型阶段标签，不代表一定正在生成reasoning内容；最终统计不保留状态标签。

最终统计保留完整中文标签：

```text
⏳ 均首字 1.2 / 首字 0.8  ⚡ 均TPS 38.6 / TPS 42.5  ⏱️ 总用时 1m23s  🔥 221k  💰 $0.087
```

七项指标合并为五组图标，平均值在组内前面。图标后固定一个空格，组间两个空格；Working 栏按整组宽度在组尾补齐空格，保证后续图标的起点稳定，但不强求组内每个数值独立右对齐。最终详细统计不添加占位空格，中文标签与数值之间保留一个空格。不显示 `tok` 后缀；首字数值仍以秒计量，但不显示 `s` 和等待省略号，总用时保留时间单位。

时延、TPS、总耗时和紧凑token数去掉小数末尾多余的零，不强制显示 `10.00`，保留原显示精度和统计精度；金额维持原有美元显示规则。Working 栏按终端可见列宽对齐，颜色转义码不占宽度；罕见超长值不截断，只扩大对应字段，本轮扩大后不缩回，下一轮恢复默认预留宽度。

Working 栏和最终统计的普通文字、标签与分隔符统一使用主题的 `dim` 弱化色，避免继承边框紫色。首字、均首字数值按延迟分档着色，TPS与均TPS数值按速度分档着色。本轮结束后，在对话区保存一条最终统计。记录不会进入模型上下文；重新打开会话时，只要本插件仍在加载，就能显示这些记录。窗口较窄时 Working 栏可能被 Pi 截短，最终记录会自动换行。

## 1. 临时加载体验（推荐先这样使用）

要求：Pi 1.4.0 或更新版本。TypeScript 由 Pi 直接加载，**不需要 npm install、编译或打包**。

先执行 `pi config`，取消勾选：

- `pi-token-speed` 的 `src/index.ts`。
- `pi-working-activity` 的 `index.ts`。

关闭并重新启动 Pi，避免旧扩展的事件处理器和定时器仍在运行。然后在终端执行：

```powershell
# 仅为这次启动加载，不修改全局安装列表。
pi -e "D:/project/tempProject/pi-round-metrics/src/index.ts"
```

进入 Pi 后发送正常提问即可。输入 `/round-metrics` 查看配置位置、当前动画及窗口设置。

需要完全隔离其他扩展时，也可使用：

```powershell
# 只加载本插件；注意这也会关闭内置 MCP 和其他扩展。
pi -ne -e "D:/project/tempProject/pi-round-metrics/src/index.ts"
```

## 2. 全局安装

确认效果满意后执行：

```powershell
# 把本地插件目录注册到 Pi 的全局包列表。
pi install "D:/project/tempProject/pi-round-metrics"
```

重新启动 Pi，之后正常执行 `pi` 即会加载，不需要再加 `-e`。

**本地安装引用的是原目录，不会复制代码。** 安装后不要删除或移动 `pi-round-metrics` 目录；要移动时，先移除旧路径，再安装新路径。不要把该目录另外复制进 `~/.pi/agent/extensions`，以免重复加载。

移除本插件：

```powershell
# 只移除本插件的安装声明，不会删除源码及已保存的配置。
pi remove "D:/project/tempProject/pi-round-metrics"
```

## 3. 手动验收

下面的操作由你在 Pi 中执行；它们会正常请求模型并可能产生费用。开发阶段没有自动运行这些场景。

| 场景 | 操作示例 | 预期 |
| --- | --- | --- |
| 展示布局 | 观察生成中的Working栏及结束记录 | 图标与本组数值之间只有一个空格，留白在组尾；整数、小数、`~` 出现或消失时后续组起点不随之跳动；结束记录保留标签并自然排版；均值在前，用 `/` 分隔 |
| 状态切换 | 分别观察模型输出、单个工具及多个并行工具的执行阶段 | 模型阶段显示“思考中”，工具阶段显示“工作中”；一个并行工具先结束时仍保持“工作中”，全部结束后才切回 |
| 单次调用 | 提问“不要调用工具，用约300字介绍滑动窗口” | 首响应前等待数值递增，收到有效原始流事件便定格，不再等正文出现；均TPS在首次调用结束前保持 `--`；生成中只有单次TPS实时变化；结束后更新均TPS并留一条统计 |
| 首包与正文分离 | 使用思考较长、正文较晚出现的模型 | 收到 `response.created`、角色首包等有效流事件后首字先定格；当前调用尚无内容时TPS保留上一有效值；最终TPS与均TPS耗时包含首包到可见内容之间的阶段 |
| 均TPS结算 | 让模型完成工具调用后继续生成较长回答 | 后续调用生成期间均TPS保持上次结算值，调用结束时更新一次；工具和首字等待不稀释均TPS |
| 首字颜色 | 观察不同首字延迟及等待时间 | ≤3秒绿色，>3～10秒黄色，>10～20秒粉红色，>20秒红色；均首字与单次首字分别着色 |
| 多次调用 | 要求“先列出当前目录文件，再读取 README，最后总结” | 新请求发出后首字从本次等待时间重新计时，TPS保留上一次有效速度；均首字不提前计入等待值，新首响应到来后再更新 |
| 工具等待 | 在测试目录让模型执行一个约5秒的无副作用等待命令，再回答 | 总用时继续增长；工具期间生成 TPS、均TPS 不被等待时间稀释 |
| 下一轮 | 完成后再发一条问题 | 不沿用上一轮；本轮请求开始后首字动态计时，TPS首次收到内容前为 `--`；平均值、总用时、token、费用重新统计，旧记录保留 |
| 中断 | 生成途中按 Escape | 留下一条标记“已中断”的统计；缺失 usage 时保留估算标记 |
| 动画切换 | `/round-metrics frames whale-spout` | 下次工作时显示鲸鱼；退出重开后设置保留 |
| 关闭动画 | `/round-metrics frames none` | 不显示动态图标，数据仍显示 |
| 颜色 | 临时把配置阈值调为 `[1, 2, 3]` 后重载，生成较长回答 | ≥3 tok/s 为绿色，TPS 与均TPS 分别判断；检查后恢复阈值 |
| 无价格配置 | 使用未配置有效价格的自定义模型 | 不把未知费用显示成 `$0`；全部未知为 `--`，部分已知为 `≥$…` |
| 历史记录 | 退出后恢复刚才的会话 | 最终统计仍可见，且不触发额外模型请求 |

默认首字/TPS只认主对话调用，不含工具内部模型、压缩模型的延迟与速度；这些额外调用若向 Pi 报告 usage，会纳入总 token 和总费用。

## 4. 七项指标的口径

“本轮”从空闲时接收用户输入开始，到 `agent_settled` 结束。不是整个会话，也不是单个底层 `agent_end`；自动重试和恢复不会提前结算。

| 指标 | 口径 |
| --- | --- |
| 首字 | 当前模型请求的 `before_provider_request` → 首个有效原始流事件。包括 Responses 的 `response.created`、Chat Completions 的角色首包、Anthropic 的 `message_start` 等；不再等待非空正文。界面沿用“首字”名称，但实际表示首响应延迟，不保证是首个生成token的延迟。等待时数值递增，到首响应便定格；不附加 `s`、`…`；工具执行期间保留已定格值 |
| 均首字 | 本轮已有有效首响应（或降级内容测量）的主对话调用，其延迟的算术平均值。只有心跳或错误而没有有效首响应的调用不纳入平均 |
| TPS | 当前模型调用的实时滑动窗口估算速度（默认最近1秒）；调用结束后定格为该次输出 token ÷ 首个有效原始流事件至消息结束的秒数，包含首包到可见内容之间的阶段。同一轮等待下一次调用时保留这个值，收到新内容后切换到新调用 |
| 均TPS | 本轮已结束且有有效生成耗时的主对话调用输出 token 总和 ÷ 这些调用生成时间总和。每次调用结束后才纳入，本次生成中保持上次结算值，首次调用结束前为 `--`。按时间加权，不对各次TPS直接做算术平均；排除首字等待与工具执行时间 |
| 总 | 用户输入接收到本轮真正结束的实际耗时，含首字等待、工具执行、重试等待及自动压缩等间隔 |
| tok | 本轮各次调用的 `input + output + cacheRead + cacheWrite` 累计；包括重复携带的上下文及缓存用量。`reasoning` 属于 output，不再重复加 |
| $ | Pi 提供的 `usage.cost.total` 累计，美元。它依赖模型价格配置与 provider 的标准化结果，不保证等于中转站最终账单 |

### 估算、修正及边界

- 流式增量没有可靠的通用逐段 token 数：实时按中文字符约1.5 token、其他非空白字符约1/4 token粗估，小数跨 delta 累加，正文、思考和工具参数均计入。
- `~` 表示输出量或计时口径存在估算。每次模型调用结束时，用真实 output usage 校正输出量；若计入均TPS的调用都有有效usage且请求、首包时点可观测，最终均TPS去掉 `~`。缺少原始流事件或请求钩子的降级测量，即使有usage也保留 `~`。当前调用的TPS在结束时从窗口估算速度切换为该次平均速度，因此可能跳变。
- 总 token 的生成中数值是“已完成调用的实际用量 + 当前调用的估算输出”，当前调用尚未返回的输入和缓存用量不在其中，因此显示 `~`；结束时补齐。
- 未返回有效 usage、仅返回部分 usage 或中断时，尽量保留已知数值与输出估算。完全未知的输入/缓存用量无法还原；这些情况下并不保证最终 token 是完整账单用量。
- 费用尚未完整返回时，有已知费用则显示 `≥$…`，否则显示 `--`。全零模型价格无法区分“免费模型”和“价格未配置”，保守按未知处理。
- 正文停止超过一个窗口时，实时TPS归零；不让上次高速读数一直停留。默认200ms刷新一次，不用固定tick次数推算耗时。
- 首字等待计时仍会递增，但只显示以秒为单位的数字。收到首个有效原始流事件便定格，不再等待文本、思考摘要或工具参数delta；等待值不会提前纳入均首字。均首字在首响应到来时更新，均TPS则等调用结束后才更新。
- TPS在新调用没有内容时保留本轮最近有效速度，不把旧值重复计入平均。只有首包且无输出时，不用0覆盖上次TPS；若最终usage报告了未透出的思考output，仍可按首包到结束的完整时间结算。工具执行期间首字和TPS保持已测值。最后一次调用无有效测量时沿用本轮此前的有效值，本轮始终没有有效值时显示 `--`；失败前的等待计时不会冒充已测首响应。
- 只观察有效的结构化流事件，过滤心跳、错误、终止和纯用量事件；HTTP响应头到达不直接视作首响应。内部区分首响应与首内容时点，输出估算仍只由内容增量驱动，不能把“收到首包”当作“生成了一个token”。
- 首包口径包含隐藏思考等可见内容之前的阶段，可避免最终output除以过短的可见生成时间。实时TPS仍是窗口内的内容估算，无法还原每个隐藏token的生成时刻，也可能受中转缓冲突发影响。与中转站核对时应优先比较同次调用的最终平均值，并确认双方是否都从首包计时。
- 原始流事件是Pi暴露的已解析事件，不是网卡上的原始首字节。协议、网络和中转站计时位置仍可能造成差异；本插件不会把本地指标保证为中转站的服务端计费或性能数据。
- 不提供或无法识别原始流事件的provider，退回首个非空正文、思考或工具参数delta，并以 `~` 标识首字及最终TPS的降级口径。没有请求钩子时退回 `turn_start` 作为起点，也以 `~` 标识。降级方式仍可能因隐藏思考而偏晚，不能与完整首包测量混为一谈。
- provider SDK 内部不暴露事件的 HTTP 重试不能拆成独立调用；计为同一次调用中的等待。自动压缩和工具嵌套调用只影响账目，不混入主对话TPS。
- 工作期间追加的纠正/排队消息随 Pi 当前活跃轮次一同结算，不在中途清零。若希望严格分轮，请等本轮结束后再发送下一条消息。
- 切换会话或 `/reload` 会释放定时器并清空实时状态，不恢复进行到一半的测量。结束记录仍然保留。计时口径更新只影响重载后的新调用，历史统计不会被重新计算。
- 只在 TUI 模式绘制 Working 栏；其他模式不创建刷新定时器，仍可保存结束记录。

## 5. 配置与动画

实际配置位置：

```text
C:\Users\liuwei\.pi\agent\round-metrics.json
```

若设置了 `PI_CODING_AGENT_DIR`，以 Pi 的 `getAgentDir()` 返回目录为准；`/round-metrics` 会显示准确路径。

配置文件不存在时直接用默认值，不会修改 Pi 全局 `settings.json`。首次切换动画时会创建本插件专用配置。也可以参考 `config.example.json` 手动建立：

```json
{
  "frames": "dots",
  "windowMs": 1000,
  "refreshMs": 200,
  "thresholds": [10, 30, 60],
  "colors": ["#ff4444", "#ff88cc", "#ffdd44", "#00ff88"]
}
```

| 配置项 | 说明 |
| --- | --- |
| frames | 动画名称，`random` 每轮随机一次，`none` 关闭图标 |
| windowMs | 实时TPS窗口，100～30000ms，默认1000 |
| refreshMs | Working数据刷新周期，50～2000ms，默认200；动画仍按各自原始帧间隔播放 |
| thresholds | 三个严格递增的正数，把速度分为四档，默认10、30、60 |
| colors | 四档颜色，从慢到快依次是红、粉红、黄、绿；只控制TPS数值着色 |

TPS默认颜色：`<10` 红色，`10～<30` 粉红色，`30～<60` 黄色，`≥60` 绿色。TPS单位均为 tok/s。

已有配置文件中显式设置的阈值和颜色仍优先，不会被新默认值覆盖。若之前手写了旧分档，请同步修改上述 `thresholds`、`colors`；`/round-metrics` 会显示当前实际生效的分界值与颜色。

首字与均首字独立按原始延迟着色（越低越好），不受TPS配置影响：`≤3秒` 绿色 `#00ff88`，`>3～10秒` 黄色 `#ffdd44`，`>10～20秒` 粉红色 `#ff88cc`，`>20秒` 红色 `#ff4444`。等待中的首字也按已经等待的时间变色；缺失值 `--` 保持浅灰色。

动画完整保留自 pi-working-activity 1.9.0：

```text
claude star2 sand triangle box box2 corners point layer flip aesthetic
hamburger moon moon8 whale-spout whale-spin comet breathe dots arrow
spark bar braille arc circle grow noise bounce bar2 dqpb toggle
```

Pi 内命令：

```text
/round-metrics                         查看当前配置
/round-metrics frames                  打开动画选择器
/round-metrics frames whale-spout      切换为鲸鱼喷水
/round-metrics frames random           每轮随机动画
/round-metrics frames none             关闭图标
/round-metrics reload                  重读手写配置
```

修改插件源码后，需执行 Pi 的 `/reload` 或重启 Pi；`/round-metrics reload` 只重读本插件配置，不重新加载源码。本地路径安装不需要重新安装。
